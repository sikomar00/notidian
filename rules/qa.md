# QA 규칙
- 기능이 끝나면 QA를 돈다. 전용 스킬은 **없음**(두 번 이상 반복되면 `skill-creator`로 만들지 묻는다).
- **Claude QA:** 수용 기준(PRD F/NF, UJ)마다 항목을 만들어 직접 실행한다. 함수 시험 → API 호출 → 내장 브라우저로 화면 클릭 순서. 결과(기대값·실제값·Pass/Fail·날짜)를 `docs/qa-guide.md`의 "Claude" 표에 등록한다.
- **사람 QA(human-in-the-loop):** 내 실제 Notion 데이터, 토큰 입력, `chrome://extensions`에 확장 올리기, 체감 속도, 문구·디자인 취향, 개인 데이터 화면은 대신하지 않고 `docs/qa-guide.md`의 "사용자" 표로 넘긴다. 항목마다 **방법 / 정상이면 보이는 것 / 주의점**을 쉬운 말로 쓴다.
- Notidian은 구글 시트를 쓰지 않고 `docs/qa-guide.md` 표에만 기록한다.
- QA 화면이 필요하면 `qa/`에 가짜 데이터로 만든 점검 페이지를 만든다. 실제 토큰·Notion 데이터는 넣지 않는다.
- 보고: 통과/실패를 숫자로, 실패는 숨기지 않고, 사용자 확인 목록 개수와 주의사항을 채팅 하단에 쓴다. 사용자 결과는 `docs/qa-guide.md`에 기록하고 실패는 Intent로 올린다.
