# 12. 사용성 과제 점검 (2026-11-14)

화면이 예뻐 보이는지가 아니라 **실제로 해낼 수 있는지**를 본다. 결과로 다음 개선(P0: 넓은 화면의 오른쪽 상세 패널·이름표 규칙·공간 활용, P1: "왜 연결됐나"·경로 찾기)의 우선순위를 정한다.

## 하는 법
- 내 실제 데이터로, 평소 쓰는 보기(옆 패널 또는 전체 화면)에서 한다.
- 과제를 읽고 바로 시작한다. 도움말·문서는 보지 않는다.
- 과제마다 아래 네 가지만 적는다: **성공/실패**, **걸린 시간(대략)**, **어려움 1~5**(1 쉬움, 5 매우 어려움), **막힌 곳 한 줄**("어디를 눌러야 할지 몰랐다" 같은 것).
- 지금 기능으로 안 되는 과제도 있다(T3). 실패도 기록할 값이다.

## 과제
| ID | 과제 | 성공 기준 | 확인하려는 것 |
|---|---|---|---|
| T1 | 내가 아는 페이지 하나를 그래프 화면에서 찾아 고르고, 노션에서 연다 | 30초 안에 연다 | 검색·고르기·열기가 바로 보이는지 |
| T2 | 그 페이지를 **가리키는** 페이지 3개의 이름을 말하고, 그중 하나로 옮겨 간다 | 1분 안에 이름 3개와 이동 | 고른 뒤 "다음 할 일"(받은 연결)이 눈에 띄는지 |
| T3 | 서로 연결된 두 페이지를 골라, **왜 연결됐는지**(어떤 문장의 @언급인지, relation 속성인지) 말한다 | 2분 안에 이유를 말한다 | 연결의 근거가 보이는지(지금은 기능이 없어 실패가 예상됨) |
| T4 | 다른 페이지와 **아무 연결이 없는** 페이지 3개를 찾는다 | 2분 안에 3개 | 외톨이를 찾는 길(목록 정렬·외톨이 숨기기·그래프)이 보이는지 |

## 결과를 보고 정하는 것
- 어려움 4~5이거나 실패한 과제의 원인을 먼저 고친다.
- T3이 예상대로 실패하면 "왜 연결됐나"(연결 종류·근거 문장 저장)를 P1의 첫 작업으로 둔다. 데이터 구조가 바뀌므로 인터뷰·문서부터 한다.
- 모두 쉬웠다면 P0 화면 개선은 줄이고 P1로 바로 간다.
