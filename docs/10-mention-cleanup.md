# 10. 언급 정리 — 계정 전체의 연결 안 된 언급 (승인 2026-11-14)

두 번째 기능([06](./06-unlinked-mentions-problem.md)~[09](./09-unlinked-mentions-spec.md))을 계정 전체로 넓힌다. 06 문서에서 "이번에는 안 한다"로 미룬 "계정 전체의 연결 안 된 언급 목록"이다. 범위가 작아 문제·화면·요구·설계를 이 문서 하나에 모았다. 용어는 [GLOSSARY](../GLOSSARY.md)를 본다.

## 1. 문제
지금은 페이지를 하나씩 골라야 그 페이지의 연결 안 된 언급이 보인다. 계정 전체를 정리하려면 페이지를 수백 번 골라야 한다. 링크를 거는 곳은 글자가 적힌 페이지이므로, **"어느 페이지를 열어서 무엇을 고치면 되는지"** 를 한 목록으로 보고 싶다.

## 2. 정한 것 (2026-11-14 인터뷰)
| 질문 | 결정 |
|---|---|
| 목록 모양 | **글자가 적힌 페이지별로 묶는다.** 한 페이지를 열어 거기 적힌 여러 제목을 한 번에 연결한다 |
| 여는 곳 | 그래프 화면 도구줄의 **"언급 정리"** 버튼. 누르면 그래프 자리에 목록이 나온다(목록 보기와 같은 방식, 새 화면·탭 없음) |
| 계산 시점 | 열 때 브라우저 안에서 계산하고 저장하지 않는다. 계산 중에는 "찾는 중…" |
| 흔한 제목 | 제목마다 **"이 제목은 빼기"**. 뺀 제목은 이 브라우저에 기억하고, 목록 위에 "뺀 제목 N개 · 되돌리기". 서랍의 연결 안 된 언급 칸에도 똑같이 적용 |
| CSV | 이번엔 넣지 않는다 |

찾는 규칙(한글 조사, 라틴 경계, 대소문자, 짧은 제목·자기 자신·이미 연결 빼기, 줄 단위)은 F-18 그대로다.

## 3. 화면 (S2-8 언급 정리)
```
[언급 정리] 버튼 (도구줄, "목록으로 보기" 옆) → 그래프 자리에
  안내: "다른 페이지 제목이 연결 없이 글자로만 적힌 곳이에요. 페이지를 열어 @언급으로 바꿔 보세요"
  뺀 제목 3개 · [되돌리기]
  ┌ 주간 회고 · 제목 3개                         [Notion에서 열기]
  │   디자인 시스템 · 2곳  "…버튼 색을 정리했다"     [이 제목은 빼기]
  │   API 명세 · 1곳      "…"                        [이 제목은 빼기]
  └ …
```
| ID | 요소 | 동작 |
|---|---|---|
| S2-8a | "언급 정리" 버튼 | 누르면 목록, 다시 누르면("그래프로 보기") 그래프. 목록 보기와는 둘 중 하나만 열린다 |
| S2-8b | 페이지 묶음 | 글자가 적힌 페이지 제목, 찾은 제목 수, "Notion에서 열기"(보기 모드별 열기 규칙 그대로) |
| S2-8c | 찾은 제목 줄 | 제목, 나온 횟수, 처음 나온 곳 앞뒤 30자(찾은 글자는 굵게), "이 제목은 빼기" |
| S2-8d | 뺀 제목 | "뺀 제목 N개 · 되돌리기". 되돌리기를 누르면 뺀 제목 목록과 각각 "다시 넣기" |
| S2-8e | 상태 안내 | 본문을 모은 적 없음("다시 만들기를 하면 보여요"), 찾는 중, 없음("글자로만 적은 곳이 없어요"), 만드는 중이면 "더 나올 수 있어요" |

### UJ-8 계정 전체 정리
1. 그래프 화면에서 "언급 정리"를 누른다. "찾는 중…" 뒤에 목록이 나온다.
2. 위에 있는 페이지(찾은 제목이 많은 곳)부터 "Notion에서 열기"를 눌러 @언급으로 바꾼다.
3. "할 일"처럼 흔한 제목이 목록을 덮으면 "이 제목은 빼기"를 누른다. 목록에서 바로 사라진다.
4. 다시 만들기 뒤에는 고친 곳이 목록에서 빠진다.

## 5. 설계
- **한 번에 찾기(`src/graph/mentionIndex.ts`, 새 파일):** 제목이 수백·수천 개라 F-18처럼 제목마다 전체 글자를 훑으면 2,000페이지에서 수십 초~몇 분으로 짐작된다(제목 하나에 50~100ms). 그래서 모든 제목을 한 번에 찾는 **Aho-Corasick 자동자**를 직접 만든다(표준 기법, 새 라이브러리 없음). 준비된 글자(`prepareTexts`)의 비교용 줄을 한 번 훑으며 맞은 위치마다 F-18의 경계 규칙을 똑같이 적용한다.
  - 같은 제목의 페이지가 여럿이면(제목이 같은 두 페이지) 같은 글자가 둘 다에 대한 언급으로 잡힌다(서랍 칸과 같다).
  - 결과 모양: `{ sourceId, mentions: Mention[] }[]`. `Mention`은 서랍 칸과 같은 타입이고 `id`는 언급된 페이지다.
- **같음 시험:** 예시 데이터와 무작위 가짜 데이터에서 "언급 정리 결과를 언급된 페이지별로 다시 묶은 것" = "페이지마다 `findUnlinkedMentions`" 를 단위 시험으로 확인한다.
- **멈추지 않기:** 페이지 50개마다 `setTimeout(0)`으로 쉬어 화면이 그려질 틈을 준다. 새로 열거나 데이터가 바뀌면 진행 중인 계산을 버린다.
- **뺀 제목:** `chrome.storage.local.ignoredMentionTitles: string[]`(NFC·소문자 제목). 서랍 칸과 언급 정리 모두 제목을 비교하기 전에 뺀다. 저장된 데이터 지우기(`clearIndex`)에서 지운다.
- **화면:** `graph.html`에 `<section id="cleanup-view" hidden>`, `src/extension/graph-view/cleanupView.ts`(새 파일). 도구줄 버튼 `#cleanup-toggle`. `main.ts`는 목록 보기 전환과 같은 자리에서 셋 중 하나만 보이게 한다(지금 446줄이라 전환 코드는 작은 함수로 묶어 500줄을 넘지 않게 한다).
- **좁은 화면:** 360px에서 도구줄 200px 이하(자동 화면 점검 기준)를 지킨다. 넘으면 좁을 때 버튼 글자를 "정리"로 줄인다.

## 6. 기본값 — 따로 묻지 않은 것
- 묶음 안의 찾은 제목도 횟수 많은 순.
- 언급된 제목을 누르는 동작은 없다(그래프에서 그 페이지를 고르려면 검색을 쓴다). 누를 수 있는 것은 "Notion에서 열기"와 빼기·다시 넣기뿐이다.
- 뺀 제목은 페이지가 아니라 **제목 글자**로 기억한다. 같은 제목의 페이지가 여럿이면 함께 빠진다.

## 7. 확인 계획
- 단위: 자동자 결과 = 페이지마다 찾기(같음 시험), 경계·대소문자·줄 경계, 순서·한도, 뺀 제목, 범례 기준.
- 속도: `qa/mentionsPerf.ts`에 언급 정리 전체 계산 시간 추가(NF-13).
- 자동 화면 점검(예시 모드): 버튼 전환, 묶음·순서, 빼기 → 목록·서랍에서 사라짐, 되돌리기, Enter, 360px.
- 사람: 내 데이터에서 목록이 쓸모 있는지, 흔한 제목 빼기가 충분한지.

## 8. 확인하지 못한 것
- 실제 계정에서 계산 시간(가짜 데이터로만 잰다).
- 제목이 아주 많을 때(수천 개) 자동자를 만드는 시간과 메모리.
