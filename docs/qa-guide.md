# QA 가이드 (구현된 범위까지 채움)

기준은 [PRD](./03-prd.md)의 F·NF이고, 확인 주체는 PRD 확인 열을 따른다. 결과는 **기대값·실제값·Pass/Fail·날짜**로 적는다. 실패는 숨기지 않고 [Intent](../Intent.md)로 올린다. 구글 시트는 쓰지 않는다.

측정 환경: 단위 시험은 Node 24.20.0, 실제 확장 점검은 **Ego Lite(Chromium 156)**. 요구 환경인 실제 Chrome에서는 아직 못 했다. 화면 확인은 캔버스 픽셀과 화면 구조 읽기로 했고, 눈으로 본 확인은 사용자 QA 몫이다. Ego Lite 창이 최소화되어 있어 그리기 시간은 재지 못했다.

## 자동 화면 점검 (npm run qa:e2e)
`npm run qa:e2e` 한 번으로 빌드한 뒤 헤드리스 Chrome에 `dist`를 확장으로 올려 화면 동작을 점검한다(P1-9, 2026-11-14 기준 111가지). 결과는 `통과 n / 전체 m`으로 나오고, 하나라도 실패하면 명령이 실패로 끝난다. 스크린샷은 `qa/e2e/out/`(git 제외).
- 쓰는 것: Node 내장 WebSocket·fetch와 Chrome 디버깅 연결(CDP). 새 라이브러리 없음. Chrome 위치가 다르면 `CHROME_PATH` 환경 변수로 지정.
- 데이터: 가짜 색인 40페이지와 가짜 토큰 자리 값. **실제 Notion·실제 토큰은 쓰지 않는다.** 화면의 Notion 주소는 가로채 가짜 페이지로 답하고, 그 밖의 Notion 주소(서비스 워커의 `api.notion.com` 포함)는 Chrome이 주소를 찾지 못하게 막는다. 이 차단도 점검 항목에 들어 있다.
- 범위: 설정 준비 단계, 범례·확대·검색·백링크·목록 보기, 지금 페이지 자동 선택, 좁은 화면(도구줄 높이·키보드 순서·대비, 밝은·어두운), 로컬 그래프, 옆 패널 따라가기. 옆 패널 자체는 헤드리스에서 열 수 없어 같은 화면(`graph.html?mode=side`)을 탭으로 연다.
- 못 하는 것: 실제 옆 패널·아이콘 클릭·실제 Notion 데이터·그리기 속도(속도는 `npm run qa`의 `qa/perf.html`).
- 확인(2026-11-13): 연달아 2번 37/37 통과. 범례 표시 코드를 일부러 망가뜨리면 그 항목만 실패(36/37, 종료 코드 1). 색인 중 단계 표시는 실제 요청을 일으킬 수 있어 화면 점검에서 빼고 단위 시험으로만 본다.
