# 8. 연결 안 된 언급 — PRD (승인 2026-11-14)

문제와 목표는 [06](./06-unlinked-mentions-problem.md), 화면 ID(S2-7·UJ-6~7)는 [07](./07-unlinked-mentions-screens.md), 첫 기능의 요구(F-1~F-15, NF-1~NF-7)는 [03 PRD](./03-prd.md)를 본다. 첫 기능의 요구는 그대로 지키고, 여기서는 새로 생기는 것만 적는다.

## 1. 범위
- 포함: F-16~F-22, NF-8~NF-11.
- 제외: 링크 자동 걸기, 계정 전체 목록, 그래프에 그리기, "DB 항목은 빼기" 옵션, 코드 블록·DB 속성 값, 목록 보기·CSV에 넣기.

## 2. 기능 요구 (F)
확인: **C** = Claude QA(함수 시험·자동 화면 점검), **H** = 사람 QA(내 실제 Notion 데이터·실제 Chrome).

| ID | 요구 | 수용 기준 | 화면 | 확인 |
|---|---|---|---|---|
| F-16 | 본문 글자 모으기 | 연결 지도를 만들며 페이지마다 문단·제목·목록·할 일·토글·인용·콜아웃·표 칸의 글자를 모아 저장한다. 코드 블록과 DB 속성 값은 모으지 않는다. 하위 블록(토글 안 등)까지 모은다. 하위 페이지·하위 DB의 글자는 그 페이지 몫이다. 페이지가 지워지면 그 글자도 지운다. "저장된 데이터 지우기"로 함께 지워진다. | S1-4 | C |
| F-17 | 처음 한 번 전체 다시 읽기 | 글자를 모은 적 없는 페이지는 "바뀌지 않았어도" 다음 다시 만들기에서 읽는다. 그때 상태 줄에 "본문을 처음 모으느라 이번엔 전체를 다시 읽어요"를 함께 보여 준다. 한 번 다 모은 뒤에는 바뀐 페이지만 읽는다(F-6 그대로). | S2-4 / UJ-7 | C, H |
| F-18 | 찾기 규칙 | 고른 페이지의 제목이 다른 페이지 글자에 있으면 찾는다. 대소문자는 가리지 않는다. 제목 앞뒤가 영문·숫자이면 그 바로 바깥이 영문·숫자가 아닐 때만 찾는다("art"는 "start"에서 안 찾음). 한글 쪽은 붙어 있어도 찾는다("회의록에서"). 빼는 것: 2글자 이하 제목, "제목 없음", 자기 자신, 이미 그 페이지로 연결이 있는 페이지(종류 무관). 페이지와 DB 항목 제목 모두 대상이다. | S2-7 | C |
| F-19 | 결과 보여 주기 | 칸 제목은 "연결 안 된 언급 N개"(N = 찾은 페이지 수). 줄마다 페이지 제목, 처음 나온 곳의 앞뒤 약 30자(찾은 글자는 굵게), 나온 횟수. 나온 횟수 많은 순, 같으면 제목 순. 50개까지 보여 주고 넘으면 "N개 더 있어요". | S2-7a·b / UJ-6 | C |
| F-20 | 결과 누르기 | 누르면 그 페이지를 Notion에서 연다. 보기 모드별 열기 규칙은 점 클릭(F-9)과 같다. 키보드(Tab·Enter)로도 된다. | S2-7c / UJ-6 | C(동작), H(실제 이동) |
| F-21 | 상태 안내 | 글자를 모은 적 없음 / 만드는 중 / 결과 없음 / 제목이 너무 짧음 / 읽을 수 없는 페이지(칸 숨김)를 [07 문서 3절](./07-unlinked-mentions-screens.md) 문구대로 보여 준다. 다시 만들기가 끝나면 열려 있는 그래프의 칸도 새 결과로 바뀐다. | S2-7d | C |
| F-22 | 예시 데이터 | "예시로 둘러보기"에 가짜 본문을 넣어, 결과가 있는 페이지·없는 페이지·짧은 제목이 모두 드러난다. | S2-7 | C |

## 3. 비기능 요구 (NF)

| ID | 요구 | 수용 기준 | 확인 |
|---|---|---|---|
| NF-8 | 찾는 속도 | 페이지를 고르고 결과가 보일 때까지 500페이지 **0.5초 이내**, 2,000페이지 **2초 이내**(가짜 데이터, 페이지당 글자 3,000자 가정). 그동안 그래프가 멈추지 않는다. | C |
| NF-9 | 저장 크기 | 500페이지 기준 본문 저장이 **10MB 이하**. 한 페이지 글자는 **10만 자**까지만 저장하고, 넘으면 앞부분만 남긴다(그 뒤 언급은 못 찾는다). 숫자는 짐작이라 실측으로 고친다. | C(가짜 데이터), H(내 데이터 크기) |
| NF-10 | 다시 만들기 시간 | 글자를 다 모은 뒤의 다시 만들기 시간이 이 기능 전보다 **20% 넘게** 늘지 않는다. | C(시험 데이터 비교), H |
| NF-11 | 요청 수·개인정보 | Notion으로 보내는 요청 수와 종류가 이 기능 전과 같다(첫 전체 다시 읽기 제외). 본문 글자는 IndexedDB에만 저장되고 브라우저 밖으로 나가지 않는다. 로그·오류 메시지에 본문 글자를 쓰지 않는다. | C(가짜 Notion 요청 기록 비교, 코드 점검) |
| NF-12 | 찾는 품질 | 내가 아는 "글자로만 적은 언급" 5개가 모두 나온다. 페이지 10곳의 결과 중 절반 이상이 "링크 걸 만하다". | H |

첫 기능의 NF-3(접근성)·NF-5(읽기 전용)는 새 칸에도 그대로 적용한다. 굵게 표시는 색이 아니라 글자 굵기로 한다.

## 4. 확인하지 못한 것
- 실제 페이지의 글자 수와 저장 크기(NF-9의 10MB·10만 자는 짐작)
- 흔한 제목·짧은 한글 제목 때문에 잘못 찾는 정도(NF-12)
- 내 계정에서 첫 전체 다시 읽기에 걸리는 시간(첫 색인과 비슷할 것으로 짐작)
