# 6. 두 번째 기능 문제 정의: 연결 안 된 언급 (승인 2026-11-14)

용어는 [GLOSSARY](../GLOSSARY.md), 결정 이유는 [ADR 0004](./adr/0004-store-body-text.md)를 본다. 첫 기능(그래프)의 문제 정의는 [01-problem](./01-problem.md)이다. 그 문서의 "그래프 말고 다른 옵시디언 기능은 안 한다"는 첫 기능 범위였고, 이 문서로 범위를 넓힌다.

## 문제
Notion에서 다른 페이지 이름을 본문에 **글자로만** 적어 두면 연결이 생기지 않는다. 그래서 그래프·백링크에 나오지 않고, 나중에 "이 페이지 얘기를 한 곳"을 찾을 수 없다. 이런 곳을 하나하나 찾아 @언급으로 바꾸는 것은 페이지가 많으면 사실상 불가능하다. 옵시디언은 백링크 아래 **"연결 안 된 언급(Unlinked mentions)"** 으로 이를 보여 준다.

> 확인한 범위: Notion 공식 API에 이 기능이나 백링크를 주는 기능이 없다는 것은 첫 기능 때 확인했다(ADR 0001). Notion 앱 자체에 비슷한 기능이 새로 생겼는지는 확인하지 못했다.

## 사용자
첫 기능과 같다. 나 혼자. 웹스토어 공개는 범위가 아니다.

## 목표
- 고른 페이지(또는 지금 보는 Notion 페이지)의 제목이 **연결 없이 글자로만** 적힌 다른 페이지를 찾아 보여 준다.
- 결과마다 앞뒤 약 30자와 나온 횟수를 보여 줘서, 페이지를 열지 않고도 그 뜻으로 쓴 것인지 판단하게 한다.
- 결과를 누르면 그 페이지가 열려, 내가 직접 @언급을 건다.

## 목표가 아닌 것 (이번에는 안 한다)
- 링크 자동 걸기(쓰기 권한이 필요해 읽기 전용 원칙이 깨진다)
- 계정 전체의 연결 안 된 언급 목록
- 그래프에 점선 등으로 그리기
- "DB 항목은 빼기" 같은 옵션
- 코드 블록·DB 속성 값 속 글자

## 제약
- 첫 기능의 제약을 그대로 따른다: 공식 API·읽기만, 브라우저 안에서만 처리, 접근 주소 두 곳.
- Notion으로 가는 요청 수를 늘리지 않는다. 연결 지도를 만들 때 이미 받는 본문을 다시 쓴다(지금은 링크만 고르고 글자는 버린다).
- 본문 글자는 내 컴퓨터(IndexedDB)에 저장한다. "저장된 데이터 지우기"로 함께 지워진다. → [ADR 0004](./adr/0004-store-body-text.md)

## 찾는 규칙
- 한글 제목은 글자 사이 어디에 있어도 찾는다(조사가 붙기 때문). 영어 제목은 단어 경계에서만 찾는다. 대소문자는 가리지 않는다.
- 빼는 것: 2글자 이하 제목, "제목 없음", 자기 자신, 이미 그 페이지로 연결이 있는 페이지.
- 찾는 대상은 페이지와 DB 항목 제목 모두. 살펴보는 글자는 문단·제목·목록·할 일·토글·인용·콜아웃·표 칸.

## 성공했다고 볼 기준
- 내가 아는 "글자로만 적은 언급" 5개가 모두 나온다.
- 페이지 10곳의 결과를 봤을 때 절반 이상이 "링크 걸 만하다".
- 다시 만들기 시간이 지금보다 20% 넘게 늘지 않는다. Notion 요청 수는 그대로다.

## 열린 질문·위험 (확인하지 못한 것)
- 본문 저장 크기: 500페이지에 몇 MB로 짐작했지만 재 보지 않았다.
- "할 일"·"메모"처럼 흔한 제목 때문에 결과가 너무 많아질 수 있다. 실제 결과를 보고 정한다.
- 이미 만든 연결 지도에는 글자가 없어서, 업데이트 뒤 처음 다시 만들기는 전체를 다시 읽는다(그때만 오래 걸린다).
- 한글 "어디든 찾기"는 "회의"가 "회의록" 안에서도 잡히는 식의 잘못 찾기가 생긴다. 얼마나 거슬리는지는 써 봐야 안다.
