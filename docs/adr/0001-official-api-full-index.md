# 공식 API와 토큰으로 전체를 읽어 색인한다

Notion에는 "이 페이지를 가리키는 페이지"를 주는 공식 API가 없어서(2026-11 조사), 모든 페이지의 본문을 읽어 연결을 직접 모아 색인을 만든다. 토큰은 **내부 통합 토큰을 읽기 전용으로 먼저 시험하고, 안 되면 개인 접근 토큰(PAT)**을 쓴다. PAT는 읽기·쓰기·검색이 한 묶음이라 읽기 전용이 불가능하고, 노출되면 Notion 내용을 바꿀 수 있기 때문이다. 상태가 `proposed`인 이유는 내부 통합 토큰의 읽기 전용 설정과 연결 범위, 서비스 워커의 CORS를 아직 시험하지 못했기 때문이다. 시험을 통과하면 `accepted`로 바꾼다.

## Considered Options
- **화면(DOM)에서 지금 열린 페이지의 링크만 읽기:** 설정은 필요 없지만 백링크가 안 되고 "모든 페이지" 그래프를 못 그린다.
- **Notion 웹앱 내부의 비공식 API:** 한 번에 읽을 수 있을 수 있지만 약관 위반 가능성(원문은 못 읽음)과 예고 없는 변경 위험이 있다.
- **공식 API(채택):** 느리지만 허용된 길이다.

## Consequences
- 처음 한 번 전체 읽기에 몇 분 걸린다(500페이지 기준 6~8분, 추정). 그래서 수동 시작 버튼, 이어 읽기, 변경분만 갱신이 필요하다.
- 검색이 완전한 목록을 보장하지 않아서, 언급으로 발견한 페이지를 따라가 빠진 페이지를 보충한다.
- 내부 통합 토큰은 워크스페이스 소유자만 만들 수 있고(시험한 계정에 그 권한이 있음을 확인했다), 읽을 페이지를 직접 연결해 줘야 한다. 상위 페이지 하나만 연결해도 하위 페이지·데이터베이스 항목이 모두 검색에 나왔다(시험 S-2, 2026-11-13). 서비스 워커의 `api.notion.com` 호출도 통과했다(S-1, Ego Lite). 실제 Chrome 확인 뒤 `accepted`로 바꾼다.
- 토큰이 내부 통합 토큰이면 읽기만 켜서 쓰기 위험을 줄이고, PAT로 넘어가면 그 위험을 설정 화면에서 경고한다.
